# 功能与操作审查报告

本报告优先记录 v1.9.0 验收。后续章节保留此前版本的审查记录；旧版时效和自动查询行为已由本版分层查询规则替代。

## v1.9.0 分层查询与配置管理（2026-11-28）

本版基于 HarmonyOS 7 / API 26.0.0 Release，SDK 编译通过。使用同一份 ArkTS 代码、独立包名和本机固定数据服务，在 API 26 模拟器控制基础状态和详情返回顺序。正式 Release HAP 使用线上接口。

| 场景 | 本版结果 |
| --- | --- |
| 首次启动、手动基础刷新 | 三站 24 插座先返回，详情请求为 0。统计、站卡状态和获取时间同步更新；无旧空态残留 |
| 主动详情查询 | 目标固定为三站共 6 个占用项，峰值并发 2；逐项显示 0/6、1/6，慢请求有提示，实测显示“已等待 10 秒”并递增至 11 秒；停止后不再发出后续目标 |
| 一项详情失败 | 显示成功 5、失败 1；点击失败重试仅新增 1 个详情请求 |
| 详情查询中刷新基础状态 | 基础请求继续成功。释放旧详情后，本轮 6 项均按已失效处理，不把旧数值写回 |
| 一站基础查询失败 | 已确认覆盖率变为 2/3，统计为 16 插座。重试失败站仅新增该站 1 次请求，恢复为 3/3 |
| 冷启动历史快照 | 基础请求尚未返回时，保存的站卡以历史显示，已确认 0/3、汇总为“—”；基础请求完成才恢复 3/3 |
| 配置复制与单站偏好 | 新建副本、编辑别名与备注、暂停并下移后保存；再复制自定义配置保留偏好。副本跨 ID 筛选选中两站并一次移除，源配置仍保留原三站；剩余一站暂停时显示全暂停态 |
| v1.8.0 覆盖升级 | 旧版保存三站自定义配置并设为当前、删除商业街，再覆盖安装本版。当前自定义及三站保留，商业街未复活。删除当前配置明确提示接替主楼 C 区，主动恢复后商业街重新可用 |
| 正式包线上查询 | 主楼 C 区三站 24 插座正常；本次点击冻结 16 个占用目标，全部完成。之后占用数变为 17 时，旧轮目标仍保持 16，不自动扩充详情查询 |
| 虚拟列表与响应式界面 | 模拟器运行中发现并修复 Builder 值捕获导致的统计、空态及站卡固化。站点卡改为接收更新参数的 V2 组件，详情变化按内容更新插座行 |

五组逻辑回归全部通过：`test-core`、`test-station-picker`、`test-refresh`、`test-monitor`、`test-network`。覆盖有序成员迁移、复制独立性、同站不同字段并发写入、写盘失败回滚、15/30/600 秒时效、128 站快照上限、429 重试期限、404 停止自动重试、手动与自动请求合并、未知与零值排序、详情停止与旧响应隔离、网络探测乱序及注销竞态。

本版未宣称真机性能、弱网体验或应用市场审核通过。真机的 P95 延迟、流量、电量、读屏、大字号和平板布局仍待实测。未签名 HAP 供允许安装未签名包的开发环境使用；真机安装需自行签名。

使用独立测试包和本机测试服务控制主楼 C 区三座站的返回顺序。测试包复用监控页及查询代码，可逐站放行或返回 HTTP 503。

使用线上接口的未签名 Release 构建也已覆盖安装，主楼 C 区显示已获取 3/3 站和 24 个插座。服务层回归另覆盖缓存站先返回、慢站不挡住后续站、按真实 ID 合并在途请求、全局四站并发上限、失败后复查和旧轮回包隔离。

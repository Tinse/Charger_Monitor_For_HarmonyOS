# 充电不愁 · 配置、站点与监控功能设计

v1.9.0 功能契约，2026-11-28 更新，基于 HarmonyOS 7 / API 26。下文描述本版实现与验收口径；真机性能和读屏仍待实测。现有测试结果见[功能审查记录](function-audit.md)。

## 一、用户要完成的三件事

| 场景 | 入口与操作 | 完成的标志 |
| --- | --- | --- |
| 出门前看哪里能充电 | 打开监控，看到上次使用的配置。先读已有数据，再逐站更新 | 能看出已确认几站、有几个空闲插座、哪些站仍待确认。返回上一页、切换配置都能继续操作 |
| 建一套自己的常用站 | 设置 → 增加配置，输入名称，按「商业街」筛选，勾选需要的站；也可复制现有配置再调整 | 新配置独立保存。已有监控选择保持原样；第一套配置自动用于监控 |
| 临时或长期调整一站 | 设置 → 配置 → 站点。可改别名、暂停监控、替换或移除；调整多站时在配置详情进入多选 | 用户在保存前知道影响哪套配置。返回监控后，成员、名称和统计范围与修改一致 |

## 二、配置管理

支持新建空配置、配置搜索、自定义改名、复制任意配置、删除和恢复缺失预设。设置点配置进入管理，监控点标签切换。删除当前配置时提示接替对象。[配置存储](../entry/src/main/ets/pages/ConfigManager.ets) · [设置首页](../entry/src/main/ets/pages/components/SettingsUI.ets)

| 操作 | 页面与规则 |
| --- | --- |
| 增 | 设置的「增加配置」支持先命名再选站，或直接保存为空配置。预设和自定义均提供「复制」。副本保留成员、别名、备注、顺序与暂停状态；有独立 ID。默认名依次取「名称 副本」「名称 副本 2」等，给后缀预留字数。保存后可点「查看配置」。 |
| 查 | 设置按「默认配置」「我的配置」分组，行内显示站数与「监控中」标记。一处离线搜索支持配置名、所含站点的别名、原站名或 ID。命中成员时显示匹配站名。进入详情再返回，保留搜索和滚动位置。 |
| 改 | 自定义配置可改名，名称为 1～24 个字符，首尾空格去除后按现有大小写规则判重。默认配置保留「主楼C区」「商业街」两个名称，成员和站点偏好照常可改。保存失败保留输入，名称冲突在字段旁说明。 |
| 删 | 「更多 → 删除整套配置」确认框显示配置名与站数。删除当前配置还应写明接替监控的第一套剩余配置；若无剩余，监控显示「增加配置」「恢复默认配置」。删除其他配置时继续当前监控。 |
| 恢复 | 恢复入口列出缺失预设，恢复出厂成员。若与自定义配置同名，指出冲突并提供改名入口。仍存在的配置保留用户改动；已删除预设只有经用户恢复才重新出现。初始预设仅主楼 C 区 3 站、商业街 19 站。 |

## 三、配置内的站点

配置详情显示站数、搜索、站点列表和固定的「添加站点」按钮。点击站点行进入单站详情。整套配置的操作统一放「更多」，管理多站时单独进入「多选」。支持别名、原名、ID 和备注搜索，以及单站编辑、替换、确认移除和跨关键词批量操作。[站点详情](../entry/src/main/ets/pages/components/ConfigStationUI.ets) · [站点选择器](../entry/src/main/ets/pages/components/StationPickerUI.ets)

| 操作 | 行为与边界 |
| --- | --- |
| 找站和添加 | 先显示已保存的站和 22 个校园站，离线即可搜索、勾选和保存。选站器支持名称、地址、ID，快捷关键词可批量勾选；换关键词保留已选项，底部列出待添加数量。已加入的真实 ID 标记「已加入」。本地未收录时可点「查找附近」并选择使用设备位置或校区位置。拒绝定位、断网或从设置返回均保留草稿；查询结果中才有的地址和距离按来源显示。 |
| 别名和备注 | 原站名和 ID 在单站详情可见。别名最多 40 字，清空恢复原名；同配置中的显式别名不可重名，原站同名用 ID 区分。新增可选本地备注，如「从西侧车棚进」，支持配置内搜索。另一套配置中的同一站有独立偏好。 |
| 排序和暂停 | 在配置详情可手动调整顺序，同时提供上移、下移。监控新增「配置顺序」，现有空闲数、功率等排序继续可选，同值按配置顺序排列。暂停后保留成员和位置，只在这套配置停止查询、退出统计；详情可恢复。全暂停时显示「所有站点已暂停」及管理入口。 |
| 替换 | 单选未加入的真实站点，确认框列出新旧名称、ID。保留用户设置的别名、顺序、暂停状态。原站的地址、插座和历史状态随原 ID 移出。备注可能记录旧站入口，默认清空，在确认框提供「保留原备注」。 |
| 移除 | 单站确认显示配置名。多选可跨筛选勾选，点数量可复核全部所选，确认后一次保存。失败时保留选择，成功后显示实际移除数。删除最后一站保留空配置，可从详情或监控直接加站。 |

查询范围须可见。配置内搜索只查本配置，选站器查校园目录、当前配置已有或草稿中已选的站，以及附近查询已返回的站。离线复制时，目录外但已保存的站也随副本保留。插座接口返回的数据不足以核实任意 ID 的官方名称和地址。

**数据归属。** 以配置 ID 保存有序成员，每个成员以真实站点 ID 标识，保存原站名、显式别名、备注和暂停标志。监控快照另按真实站点 ID 保存。旧版以显示名映射 ID，升级时按可读出的原顺序迁移，保留已有原名、当前配置及预设删除记录；缺少原名沿用既有名称，不根据别名猜测。配置写入串行，在最新状态上按 ID 提交本次变更。迁移和批量操作均在整笔写入成功后更新界面，写盘失败保留上次完整版本，可重试。未保存的表单返回时提供「继续编辑」「放弃修改」。

## 四、监控页如何显示和更新

基础状态与占用详情分开获取。基础状态逐站返回并更新覆盖率；每站成功后 15 秒进入自动复查，30 秒退出已确认汇总。跨进程保存基础快照，最长显示 10 分钟历史。详情仅通过按钮显式获取。[缓存](../entry/src/main/ets/pages/utils/DataCache.ets) · [站点服务](../entry/src/main/ets/pages/services/StationService.ets) · [插座接口](../entry/src/main/ets/pages/api/ChargerApi.ets)

### 首屏与统计

1. 立即显示当前配置和启用的站点行。内存中有可用状态就填入，否则读取设备上最后一次成功的基本状态。一座站收到有效插座列表就更新该行和汇总。没有记录的站始终占一行，显示「待查询」或「查询失败 · 重试」。
2. 顶部显示「已确认 X / Y 站」及已确认站的空闲、占用、故障和总数。Y 是当前配置启用的站数，搜索只过滤列表。若 3 站中 2 站成功、两站均无空闲，应显示「已确认 2/3 站，已确认站点空闲 0」，并列出待确认的第 3 站。X 为零时数字显示「—」。只有全部启用站均已确认且空闲为零，才显示整套配置「暂无空闲」。
3. 行内有「获取于 12:32:05」「更新中」「上次记录」「重试」等状态。获取时间取客户端收到有效站点状态的时刻。读缓存、刷新失败、补到一条功率或费用，都不能推进该时间。页面更新保留滚动锚点，详情补全不打断查看。

### 缓存、时效与失效

下表按距上次成功获取基本状态的时间计算。**15 秒是启动复查的目标，30 秒是仍可计入已确认汇总的上限。** 网络慢或服务故障时，状态可以退回历史，不承诺设备端插座在时限内一定发生上报。

| 情形 | 立即显示 | 网络动作 |
| --- | --- | --- |
| 内存记录不足 15 秒，最近一次查询成功 | 按本配置的别名和顺序显示，计入汇总 | 自动进入或切换时复用，手动刷新可立即复查 |
| 满 15 秒、不足 30 秒，尚无失败 | 保留数值；请求开始后标「更新中」 | 监控可见即按到期站点补查，在途请求合并 |
| 满 30 秒、上次复查失败、已知离线，或冷启动只读到磁盘记录 | 有 10 分钟内的记录，标「上次记录」并退出已确认汇总；无可用记录显示「—」 | 在线且可见时复查；离线保留列表，网络恢复后只补一次 |
| 记录已满 10 分钟、时间戳无效或时钟回拨导致年龄不可信 | 显示站名和「状态待确认」，不展示过期插座数 | 首次可查询时重新获取 |

磁盘仅留已配置站点的最近一次有效基础快照和时间，冷启动可读。费用、充电时长、设备位置不随快照落盘。最近使用的最多 128 站保留历史，超时或失去所有配置引用后清理；缓存损坏只影响状态回显，配置仍可用。附近目录有独立的短期内存缓存，区分校区与设备位置，重新定位仅刷新附近目录。不同配置的同一站共用状态，各自应用别名和偏好。

以商业街 19 站持续可见为例，每站成功后 15 秒再查，稳定运行时基础查询上限约为每分钟 76 次（慢请求、后台与退避会降低次数）。首屏、手动刷新、失败重试和详情请求应分别计数。真机验收同时记录流量与限流响应，再决定是否调整周期；后台、暂停站以及只改名称的操作不消耗这笔自动查询预算。

### 请求调度与交互

- **自动与手动。** 仅在应用前台、监控页可见时调度自动复查；回前台立即比较年龄，后台不补积压的轮次。按钮和下拉只刷新当前启用站，单站重试或「重试失败站」只查失败项。三种入口共用在途任务、3 秒手动冷却和结果反馈。3 秒后慢请求仍显示「更新中」。下拉在一张卡的短列表也应能触发。[华为 ArkUI Refresh 指南](https://developer.huawei.com/consumer/cn/doc/harmonyos-references/ts-container-refresh/)
- **合并规则。** 每个站先复用正在进行的基本状态请求。手动全量刷新遇到只查部分站的自动轮次，复用重叠的站，只补其余启用站。冷却从一次被接受的手动触发算起，只限制下一次新手动轮次；自动任务不启动冷却。页面可见时，记录达到 30 秒和 10 分钟的边界要按时更新显示，即使网络一直没有回包。
- **先回答有没有空位。** 基础状态使用可连续补位的 4 路请求队列，一个慢站只占一路。启动、定时、手动刷新、滚动、展开与排序均只获取基础状态，不触发详情查询。
- **主动查询占用详情。** 单击「获取占用信息」后，固定当前配置全部启用且已确认站点的占用插座清单，搜索不缩小范围。详情最多并发 2 个，基础请求和详情互不阻塞。显示已处理/总数、成功、失败和状态变化数，3 秒提示仍在查询、超过 10 秒展示已等待秒数；可停止排队、只重试本轮仍有效的失败项。已发出的请求可能继续返回，但停止后的回包不再更新页面。
- **详情时效与排序。** 功率、费用、时长显示各自可用值，缺失值为未知，零值正常显示。基础状态刷新后，仍处于占用状态的已成功获取详情保留，获取时间保持不变；暂时离线或未确认时仍可查看历史值，但不计入已确认统计。检测到空闲、故障、成员移除、暂停或基础记录过期时移除详情，不带入之后的新占用。详情重新获取失败或停止时保留上次成功值。未完成请求仍按基本状态世代隔离，迟到的旧详情丢弃，未发出的旧目标跳过。按详情排序只比较已经主动获取的值，未知排末尾，同值沿用配置顺序；始终保留「获取占用信息」入口。
- **配置变化。** 修改名称、别名、备注和顺序只重绘。切换配置以 ID 比较成员，复用共有站，只请求新增、缺失或到期站。移除、暂停时立即退出汇总。页面使用当前配置版本过滤回包；同一 ID 的较早响应不能覆盖较新的成功结果。附近重查与监控刷新互不清缓存。
- **故障。** 无网时暂停自动请求，恢复网络且页面可见时合并为一次复查。临时故障按站采用 15、30、60 秒封顶的自动退避，成功后复位。手动重试可提前。若服务给出重试期限，按服务指示的范围约束对应站点或整个接口，手动与自动均遵守。只有上游明确表示站点不存在时才停止该站的周期重试，保留原记录时间，提供「重新核实」「替换站点」。超时、异常响应、无可用数据均按查询失败处理。[HTTP Retry-After 语义](https://www.rfc-editor.org/rfc/rfc9110.html#section-10.2.3)
- **计算与反馈。** 仅在成员、数据或新鲜状态变化时重算汇总。倒计时、滚动和搜索不遍历全部插座。读屏在用户主动刷新结束时播报一次结果，按钮和状态同时有文字语义。离开监控看内置地图或设置时停止新增轮询，返回同一配置保留筛选与浏览位置。

## 五、实施顺序与验收

| 顺序 | 交付范围 | 进入下一阶段前的检查 |
| --- | --- | --- |
| 第一阶段 | 监控按站 ID 缓存与合并请求，拆分状态和详情，逐站更新，覆盖率、离线和失败态 | 用可控时钟和测试服务跑过下表的缓存、并发和乱序场景；当前的倒计时、下拉和真实获取时间回归继续通过 |
| 第二阶段 | 配置搜索、所有配置可复制、成员结构迁移、按差异更新监控；离线选站和显式查找附近 | 覆盖从已有开发数据、v1.8.0 数据和全新安装进入；核对两套默认、用户已删预设、所有自定义配置与当前选择 |
| 第三阶段 | 备注、手动顺序、暂停与恢复、批量移除；API 26 模拟器发布验收 | 覆盖跨配置、批量写入、生命周期与升级。真机弱网、读屏及性能列为后续验证，不以模拟器结果替代 |

| 验收场景 | 可观察结果 |
| --- | --- |
| A 配置有站 1、2，B 有站 2、3；站 2 刚查过。切到 B，同时让 A 的慢响应返回 | B 只新查缺记录的站 3。站 2 使用 B 的别名；旧卡片和旧汇总不会出现。单改别名产生 0 个监控请求 |
| 3 站已有数据，手动刷新时 1 站失败；随后只重试失败站 | 3 张卡都保留；汇总显示 2/3，失败卡带旧时间。重试只请求失败 ID，成功恢复 3/3。断网冷启动 9 分钟前的记录可查，10 分钟前的数值隐藏 |
| 一站上次成功后持续可见，复查请求始终未返回；用可控时钟推进 | 14 秒仍复用，15 秒开始复查。29 秒仍标「更新中」并计入汇总，30 秒退出已确认数。599 秒可查上次记录，600 秒隐藏旧数值 |
| 19 站，其中一站延迟 5 秒。按钮、下拉、自动刷新几乎同时触发 | 其他成功站先出现；同站同轮只有一个基本状态请求。检查请求日志中站点基础并发 ≤4、详情 ≤2、监控总并发 ≤6 |
| 两套配置共用一站。复制自定义配置，改名、备注、排序、暂停，替换后再删除源配置 | 删除前按两个配置名均能找到各自配置，偏好独立，暂停项退出分母，替换后顺序保留且旧插座值消失。删除后只搜到副本，重启后仍可用。删最后一站可再添加，删最后一套可新建或恢复 |
| 筛选后跨组批量添加、移除，分别测试取消、写盘失败、重启和重试 | 取消保留原数据；写盘失败所有配置成员一致、草稿可继续；重试成功只提交一次。迁移重试不重复建站、不恢复 D 区 |
| 拒绝定位并断网，使用校园预设建配置；之后主动查找附近并返回。再停留地图、设置或后台各 2 分钟 | 离线建配成功，授权返回保留关键词和勾选，最多补查一次附近。监控离开可见状态后新增自动请求为 0；返回只查到期项 |
| API 26 真机分别使用 3 站、19 站，跑冷启动、热切换、弱网和系统大字号、读屏 | 在记录的基准设备上，各场景至少 30 次；目标为已有缓存时，从监控页可见到第一条状态显示 P95 ≤300 毫秒。另记首站联网更新时间、整套完成时间及请求峰值。大字号和读屏下可独立完成搜索、选站、刷新及删除确认 |

这组验收先验证显示是否可信，再衡量速度。缓存首屏、首站更新和整套完成分别计时，任何单一平均值都无法区分本地显示慢、详情接口慢和某个站点失联。
